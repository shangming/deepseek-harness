# Agent Note: 把选中的对话正文引用进输入框

Status: implemented

[English](2026-09-19-transcript-quote-surface.md) | 中文

## Problem

用户常常要针对早先某条消息里的一段话作答：既想指出那一段，又想说明自己对它的看法。界面没有提供这样的途径。手工选中并复制那段话，会让引文与回答之间没有边界；唯一的结构化替代是跨会话 `@` 引用，而它快照的是另一个会话的整体，既不属于当前对话，也无法只取选中的那一段。

## Decision

新增客户端插件包 [ui-message-quote](../../../../packages/client/ui-message-quote/README.zh.md)，向 `conversation.input.overlay` 贡献一个浮出动作。该动作跟随正文滚动容器内的非空选区，点击后把选中文字以 Markdown 引用块写入输入框，并在其下留出一空行供用户写评论，随后把键盘交还输入框。

引用是用户可见的文本。它不需要宿主服务、Remote、Session 事件或请求期上下文：用户提交的消息本身带着引用，因此 Session 日志能精确复现它，模型读到的就是用户自己写下的文字。引用块不带出处，因为解释这段话为何重要的正是用户自己的评论。

动作以选区为粒度，而不是以消息为粒度。它读取文档选区并锚定到首行矩形的并集，因此任何正文文字都可引用——助手回复、用户消息或工具输出——引用界面无需依赖消息身份、消息动作槽位或逐条消息的注册。滚动与缩放时它选择隐藏而不是追踪已经移动的锚点，因为过期的锚点会飘离它所引用的文字。

输入框聚焦经由一个注入动词完成。公开的 `InputActions` 面没有聚焦操作，因此条目的注入面通过该 Session 的绑定解析输入门面（`sessions.binding(sessionId).ctx.get('conversation')?.input.for(actx).focus()`），而不是让插件另找第二个写入者，也不是让界面用 DOM 查找去聚焦输入框。

## Alternatives considered

**把 `session-reference` 扩展到消息粒度。** 该解析器已经拥有不可信快照的框架、字节预算与 spill。但它拒绝自引用、快照整个会话，并把结果作为另一条隐藏消息注入——这与用户想引用一段话的诉求正好相反：用户希望评论与引文在同一条可见消息里，并且引文停在自己放的位置。

**在消息动作行里加一个「引用」条目。** `conversation.chat.assistant-actions` 会为每条已定稿的助手消息放置一个控件，但用户选中的单位并不是消息：真正有意思的往往是一句话或一段代码，而用户消息根本没有动作槽位。逐条消息的控件也无法表达「就是这一段」，除非再在自己的弹窗里加一次选中步骤。

**用宿主插件在 `agent/pre-step` 注入引用。** 这样界面可以把引用从可见消息中剥离、再作为上下文加回。此处它毫无收益：用户挑选的文字，其正确归属就是用户消息本身，而一份隐藏副本会让日志与模型请求对「用户究竟发了什么」产生分歧。

**为引用引入临时标记或新的 Session 事件。** 新事件类型必须进入 surface 的消息产出集合，以及所有重建请求的读取路径，而它承载的内容本就可以用用户文本表达。

## Consequences

用户无需离开输入框即可引用并回答某一段话，发送侧不需要任何新协议。代价是新增一个客户端包及其注册面，以及包 README 记录的四条限制：引用是纯文本、不保留原有标记；替换草稿会把其中已有的引用 chip 退化为剪贴板文本；引用不带出处；只有指针选区才会浮出动作。
