# @deepseek-ai/dsh-client-ui-message-quote

[English](README.md) | 中文

## 概述

本包提供 Web 引用界面。在对话正文中选中非空文字后，选区上方浮出一个动作；点击它会把选中文字以 Markdown 引用块写入输入框，并把键盘交还输入框，用户想写的评论自然落在引用块下方的那一空行上。本包只向输入框浮层槽位贡献一个条目，不需要宿主服务、Remote 或新的 Session 事件：引用随用户发送的那条消息，以普通用户文本到达模型。

<a id="use-this-package"></a>
## 使用本包

只要组合挂载了本包，界面即生效。浮出动作与它写入的引用都不需要宿主支持。

### 动作出现的位置

动作跟随一个未折叠、非空，且起点位于对话正文滚动容器（`[data-conversation-scroll]`）内的选区。输入框、侧边栏与外壳界面都在该滚动容器之外，因此在那里选中文字不会浮出任何东西。助手回复、用户消息与工具输出都可引用，因为动作读取的是选区，而不是消息身份。

每个已挂载的输入框只回应自己那段对话的正文，范围由包含它的内容根节点确定。输入框链在由业务接管的输入框生效时仍保留一个被隐藏的兜底输入框，而动作渲染在文档根节点上，隐藏对它并不生效；若没有这层范围限定，一个选区会在每个已挂载的输入框上各浮出一个动作，点击还可能写进用户看不见的输入框。

动作居中于选区首行各矩形的水平并集，并位于该行上方 8 像素处。一行文字跨越行内元素时会报告多个矩形，取并集才能让动作停在用户真正选中的那段文字上方。

选区折叠或变为不可引用、正文滚动、窗口尺寸变化时，动作隐藏。滚动和缩放会移动选中文字但不改变选区，若继续显示，记录下来的视口锚点就会落在文字之外。在动作上按下指针会保留选区，否则这次按下会在点击到达之前先把选区折叠掉。

### 选中后的写入结果

选中后，输入框草稿会被替换为「原有文字 + 其下的引用块」，键盘交还输入框，光标停在引用块下方的那一空行上。

| 选中的文字 | 选中后的草稿（原草稿为空） |
|---|---|
| `first` | `> first`，再空一行 |
| `first` 换行 `second` | `> first`、`> second`，再空一行 |
| `first`、空行、`second` | `> first`、`>`、`> second`，再空一行 |

每一行选中文字都加上 `> ` 前缀，选区内部的空行变成单独的 `>`，选区自身首尾的空行被丢弃，因此引用块既不以空标记开头也不以其结尾。回车换行统一为换行符，每行末尾空白被去掉；行首空白保留，缩进代码的缩进不变。草稿中已有的文字留在引用块之上，其末尾空白同样被去掉。

发送出去的消息就是引用块加上用户在其下写的内容。没有任何标记说明它由界面插入，模型收到的就是用户手写引用块时的同一形态。

## 理解实现

<details>
<summary>实现细节 —— 点击展开</summary>

本包贡献 `conversation.input.overlay`（输入框卡片上的浮层槽位）中 id 为 `message-quote`、order 为 3 的条目，并透过 portal 渲染到文档根节点，使正文滚动容器与输入框卡片都无法裁剪它。条目的注入面只带一个动词 `focusComposer`：它经由持有该 Session 的绑定解析出该 Session 的输入门面并调用其 `focus()`。

| [`src/client/QuoteAction.tsx`](src/client/QuoteAction.tsx) | 浮出动作：选区跟踪、锚定与写入 |

### 选区读取与锚定

`readTranscriptSelection` 取文档当前选区，拒绝缺失、折叠或纯空白的选区，并从 range 的公共祖先向上走到正文滚动容器。`selectionAnchor` 随后把与首行重叠的矩形取并集，返回该行的水平中心与上边缘；若没有任何有面积的矩形，就没有锚点，动作也不会出现。

### 组合状态

组件只保存当前选区锚点。它拼接的草稿来自 Session 输入状态库，组件通过标准的 `useInput` 席位读取，因此每次写入都接在输入框当下的内容之下。输入框聚焦走注入的 `focusComposer` 动词而不是第二个写入者：门面按 Session 经 `sessions.binding(sessionId).ctx.get('conversation')?.input.for(actx).focus()` 解析，对没有绑定的 Session 调用注入会显式失败。

### 为什么没有宿主插件

引用就是用户文本。发送它不需要新的 Session 事件、不需要 `agent/prestep` 贡献、也不需要请求期上下文：用户提交的消息本身就带着它，重放能从 Session 日志逐字节复现。

<a id="model-experience"></a>
## 模型体验

### 用户消息中的引用文字

#### 模型看到什么

引用属于用户自己的消息：选中的各行以 Markdown 引用行（`> text`）到达，随后是用户写在其下的评论。没有任何标记说明引用由界面插入，因此其形态与用户手写的引用块完全一致，请求中也不带第二条消息或隐藏上下文。

#### Token 影响

引用只消耗其自身文本的 token。它是普通消息内容，会一直留在历史中，直到压缩遮蔽或摘要了那条消息；重复引用同一段文字不会去重。

#### KV Cache 影响

被引用的消息是一条只追加的用户消息：此前的可缓存历史不受影响，请求之间只有新的后缀不同。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>


这些限制界定了当前引用界面的适用范围，是本包的现状约束，不是待办清单。

- **仅纯文本** —— 引用是浏览器报告的选区文本。行内代码、链接、强调、表格与图片只会以文字到达，产生它们的标记不保留。
- **草稿被整体替换而非原地编辑** —— 输入框的公开写入路径替换整个文档，因此草稿中已有的引用 chip 会退化为其剪贴板文本（`@path`、`@[label](dsh-session:…)`）而失去 chip 形态。模型可见内容不变，且这次插入并入同一个撤销步骤，而不自成一个步骤。
- **引用不带出处** —— 引用不标注消息、说话人或时间，模型无法判断它出自对话中的哪一处；必要时由用户的评论补上这层上下文。
- **仅指针选区** —— 动作只响应文本选区；没有键盘入口、没有快捷键，消息动作行里也没有逐条消息的「引用」控件。
- **没有矩形的选区不可引用** —— 动作需要一个可测量的首行来锚定，因此 range 报告不出任何矩形的选区不会浮出任何东西。
